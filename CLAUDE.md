# Stryguard

Fun, self-updating website (plus an in-game addon) for **Stryguard**, an Alliance guild on
World of Warcraft: Forever, EU, Roleplay PvP. Guild slug `stryguard`, ~28 characters.
The user runs the guild.

- Live site: https://stryguard.github.io (repo github.com/Stryguard/stryguard.github.io, branch `main`)
- `README.md`: how the site works, for humans. `HANDOVER.md`: original 14 Nov 2026 context and
  Blizzard API probe findings. Parts of HANDOVER are now stale (see "Stale in HANDOVER" below).

## Rules

- **The secret:** never read, print, echo, log or save the `BLIZZARD_CLIENT_SECRET` environment
  variable. Check presence only: `py -c "import os; print(bool(os.environ.get('BLIZZARD_CLIENT_SECRET')))"`.
- **Windows:** run Python with `py`, not `python`. (CI uses `python3` on Ubuntu.)
- **Fun first:** whimsical stats only. No item level, character stats, talents or raid min-maxing
  unless the user asks.
- **Standard library only** for `fetch_roster.py` and `addon/tools/make_maps.py`.
- **Site page rules:** `site/index.html` stays one self-contained file. It fetches only its own
  JSON files (`data/stryguard-roster.json`, `guild.json`, `firsts.json`, `history.json`,
  `milestones.json`). Only other outside resources: Google Fonts, and member-card portraits as
  `<img>` from `https://render.worldofwarcraft.com/` (checked against `PORTRAIT_HOST`, falls back
  to an initial on error). Data values go in via
  `textContent` (the `h()` helper), never `innerHTML`. `localStorage` is only for viewer prefs
  (theme, Norwegian mode), always in try/catch.
- **Design:** "Codex" look (parchment + oxblood, Cormorant Garamond / Alegreya / Grenze Gotisch).
  Full-width rows in reading order on desktop, single column on phone, low clutter, no boxes in
  boxes. Light and dark themes.
- Commit or push only when asked.

## Layout

```

site/firsts.json           Bot-written ledger of who claimed each milestone first. Don't hand-edit.
site/history.json          Bot-written daily snapshots (last 15 days, UTC date).
site/data/                 Generated by the workflow; gitignored.
.github/workflows/update.yml   Hourly (:23), on push to main, and manual. Fetch -> commit
                           firsts/history -> deploy site/ to Pages.
stryguard-roster.html      OLD claude.ai artifact tracker. Reference only (see below).
stryguard-probe.json       Probe report of every character endpoint for "Old Iron".
addon/                     Stryguard Skywatch WoW addon (committed 23 Nov 2026; not deployed).
```

## fetch_roster.py

- OAuth client credentials. `CLIENT_ID` hard-coded (not secret). Secret from env or hidden prompt;
  exits if missing and stdin isn't a TTY (CI).
- Env: `BLIZZARD_CLIENT_SECRET`, `WOW_REGION` (eu), optional `BLIZZARD_CLIENT_ID`, `WOW_GUILD`.
- Namespace `profile-forever-eu`, locale `en_GB`. Roster `/data/wow/guild/stryguard/roster`,
  characters `/profile/wow/character/{first}-{last}` lowercase (roster entries carry `slug`);
  slugs are URL-encoded (Aulë, Bjørnson work).
- Per member ~12 requests; full run ~40 s. The `fun` object holds statistics (falls, drownings,
  hugs, food...), boss kills, deeds (achievements), pets, mounts, reputations, looks, gear names,
  titles, portrait URLs.
- Flags: `--out DIR`, `--no-fun`, `--debug`, `--probe "Name"`, `--ledger FILE`,
  `--milestones FILE`, `--history FILE`.
- Local run:
  ```sh
  py fetch_roster.py --out site/data
  py -m http.server 8000 -d site      # open http://localhost:8000
  ```
- Forever API is undocumented; field names can change. If something breaks, re-run
  `py fetch_roster.py --probe "Old Iron"` and compare with `stryguard-probe.json`.
- Achievement points are always 0 in Forever. Stat quantities are floats.

## site/index.html sections

Nav tabs over these `<section>`s: `oddities` (hall of oddities / awards with crowns), `crier`
(Town Crier weekly edition, Sundays from 22 Nov 2026), `firsts` (guild firsts: milestones +
Armory-dated achievements), `race` (levelling race, incl. Total XP view), `makeup`, `totals`,
`deeds` (recent achievements feed), `boards`, `trophies` (OSRS-style boss kill counts per boss and
per character), `friends` (pets/mounts), `roster` (sortable, member card dialog, `#hash` deep
links). Extras: secret Norwegian mode (`toggleNorsk`), theme picker, snowfall/party toasts.

Entry points: `load()` -> `buildMembers(roster, guild)` -> `render()` calls each `renderX()`.
Award definitions live in `shelves()`.

## Workflow and git gotchas

- The bot commits "Update guild firsts and history" to `main` about daily. **Always
  `git pull --rebase` before pushing**, and expect local `main` to be behind origin.
- Every push to `main` triggers a deploy. Only `site/` is published.
- GitHub pauses scheduled workflows after 60 days with no repo activity.
- Blizzard limits (36,000/h, 100/s) are far above our ~350 requests/run.

## Stryguard Skywatch addon (`addon/`)

Tower defence campaign for long flights. Opens on taxi (`PLAYER_CONTROL_LOST`), pauses on landing,
hides in combat. `/skywatch` or `/td`. Interface `16001` (Forever client). Version 3 (22 Nov 2026)
grew it ~10x: 60 levels in 10 chapters, 24 towers (9-slot armoury loadout), ~150 foes/bosses,
107 blessings, 43 shop items, 16 affixes, Heroic mode, ~100 deeds. See its README for the player view.

- Load order (`.toc`): `Maps.lua` (generated rows) -> `Data.lua` (towers + specs as add/mul/set
  data, affixes, blessings, shop, MakeWave; board 22x13 at 26 px) -> `Foes.lua` (foes, bosses,
  intros; cost/gap/gold auto-computed from stats + abilities) -> `Levels.lua` (chapters; ch2-10
  levels built from a list + formula; `ns.TUNE` = per-level hp from bot tuning) -> `Deeds.lua` ->
  `Meta.lua` (marks, shop, loadout, campaign + heroic, stats, deeds) -> `Game.lua` (simulation,
  no UI; attacks by `st.attack`) -> `UI.lua` -> `Core.lua`.
- SavedVariables `SkywatchDB`: marks, shop, campaign (`cleared, stars, heroic, endless`), loadout,
  deeds, stats, opts, run (snapshot `v = 3`; `v = 2` still restores).
- Maps: `py tools/make_levels.py` writes `Maps.lua` (chapter 1 hand-drawn in `HANDMADE`, the rest
  generated deterministically from the key; roads on a 2-spaced lattice so road squares never
  touch). Then `py tools/make_maps.py [keys|atlasN] [--png DIR]` paints `media/`: chapter 1 one
  TGA each (26 px squares), the rest 4 per 1024x512 `atlasN.tga` at 18 px squares (UI picks the
  slot by texcoords). ~4 s a map. Map letters: S lair, E keep, # road, . ground, T trees,
  ~ water/lava, G props, R rocks (Mining Camps build on R, Harbor Batteries on ~).
- **Testing without WoW** (no Lua installed; use a venv with `lupa`, Lua 5.1): a headless
  harness loads the game files and lets a bot play (`harness.py`), `tune.py` sets `ns.TUNE` so the
  bot's lowest winning shop rank follows chapter c, level i -> c + (i-1)/5, and `uitest.py` loads
  everything against a mock WoW frame API and fuzz-clicks the UI. These lived in the session
  scratchpad, not the repo; recreate them if needed. The bot is weak, so tuning is a curve, not
  a promise; real playtests should adjust `ns.TUNE`.
- Icons: names are vanilla-era guesses; a wrong one shows as a blank/question mark, not an error.
- Install path: `C:\Program Files (x86)\World of Warcraft\_forever_\Interface\AddOns\`.
  `/reload` for code; new textures need a full game restart.
- Committed in this repo (23 Nov 2026) but not published: only `site/` deploys to Pages.
